# Security policy

This is a single-user, offline, synthetic-data educational lab. It does not control real energy systems or expose a public multiuser service. Do not bind/proxy it publicly or submit confidential facility data. No account store, remote fetches, uploads, plugins, advertisements, analytics, external fonts or AI APIs exist. The app intentionally has no user-data collection.

Defense layers: strict finite/bounded local input schema; 64KiB JSON limit; loopback bind; exact Host and same-origin checks; no CORS, uploads or mutating HTTP; static-path confinement; restrictive CSP/no framing/nosniff; escaped report HTML/text-only report rendering; no shell from model input; bound SQL; dependency hashes/locks; SHA-pinned least-privilege Actions, dependency audits and CodeQL. Failures hide stale evidence. These reduce attack surface; they do not guarantee absence of bugs or protect against a compromised OS/local user. Standard-library threaded HTTP is not Internet hardened or a resource-exhaustion sandbox. SQLite is unencrypted; filesystem permissions remain your responsibility.

Releases are unsigned. Verify SHA-256/source and OS policy; do not bypass warnings or disable protection. Hashes do not prove trusted authorship. Only install downloads from the intended repository/release. Runtime data, environments, databases and build outputs are Git-ignored. Never post secrets in issues. For suspected security issues use GitHub's private vulnerability reporting if available; otherwise contact Jason Stys through his GitHub profile without disclosing exploit details or sensitive information publicly.
